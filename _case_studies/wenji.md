## 业务背景 {#context}

问迹面向案件中的多源电子检材，覆盖数据接入、Agent 研判、线索发布与原文核查，为线索挖掘、人物画像和专家研判提供可追溯的分析能力。

这类任务需要连续处理文件、调用工具并汇总结果。随着任务变长，执行状态、上下文边界、工具访问权限与结果来源都会影响系统的可用性。

## 我的职责 {#responsibility}

Agent 侧由 **3 名核心开发**负责。我负责的模块覆盖异步任务引擎、多 Agent 编排、Skill 管理、上下文记忆、Agent 评估与线索溯源。

- **任务运行：**设计 Java—Agent 异步任务引擎与任务级独立工作区，维护执行边界和状态流转。
- **协作与工具：**设计方案/战法驱动的多 Agent 编排，建设版本化 Skill 与受控 Tool 体系。
- **结果与验证：**构建候选线索到原文的来源链路，以及分层记忆和自动化评估流程。

## 设计与取舍 {#design}

### 01 / 分开管理任务状态与 Agent 执行

Java 负责任务持久化、消息投递和状态流转。Agent 消费任务后，为每个任务建立独立工作区，管理文件、脚本、进程上下文与分析产物。

任务状态覆盖排队、执行、等待、成功、失败、取消和超时。配合路径校验、工具白名单、超时终止与资源回收，将模型执行放进明确的任务生命周期中，便于追踪运行进度与异常退出。

### 02 / 围绕任务边界组织多 Agent 协作

根 Agent 按方案/战法拆解任务，调度独立 Worker；结合“分析模式 × 数据形态”选择执行链路。

这一拆分用于处理单 Agent 上下文膨胀与执行边界混乱的问题。角色、工具白名单和真实产物对账共同约束 Worker 的工作范围，支持战法级上下文隔离、无依赖任务并行与异常结果拦截。

### 03 / 让 Skill 与 Tool 可管理、可审计

Skill 管理统一覆盖系统/用户 Skill 的创建、上传、导入导出、版本与可见性。

数据库访问通过受控 DBTool 封装物理表映射、数据范围校验与结果返回，结合角色白名单和任务级审计限制越权查询及模型直接拼接 SQL。工具能力与访问约束一起维护，使任务执行具备可追踪的调用记录。

### 04 / 让线索能够回到原文

候选线索、证据口径与完整来源集合保持绑定。来源信息包含源文件版本、Sheet/页码、行列坐标和字符偏移，支持表格单元格级定位、文本段落字符级高亮与原文核查。

在线索发布前校验来源归属、数量、唯一性、内容摘要与物理位置，让结果核查有明确的落点。

### 05 / 用记忆与评估支持持续迭代

工作记忆维护当前任务状态并压缩冗余上下文；长期记忆检索可复用信息。评估结合轨迹回放、规则校验与 LLM-as-Judge，对不同 Agent、模型和 Skill 版本进行回归比较。

## 规模与验证 {#validation}

以下数字分别描述项目的任务规模、能力管理范围与测试覆盖，保持各自的统计口径：

- **任务规模：**单任务最长运行 6 小时，最大处理 30 GB 数据。
- **Skill 管理：**纳管 37 个内置 Skill。
- **来源回归测试：**覆盖 24,014 条来源记录。
- **评估维度：**任务完成、工具调用、来源完整性、Token 消耗与执行时延。

这些实践让我持续关注 Agent 应用中的任务生命周期、工具约束与来源核查。它们共同支撑从模型调用到业务交付的过程。
