## 业务背景 {#context}

智慧图书馆需要与高校既有业务系统协同。不同学校的数据字段、认证协议、业务规则和部署环境存在差异，通用产品需要通过接口与配置适配各校的具体场景。

我在北京超星移动图书馆产品部负责校内异构系统对接，工作覆盖数据同步、统一身份认证、高校定制接口与私有化交付。

## 我的职责 {#responsibility}

- **读者数据同步：**开发全量初始化与定时增量同步，处理数据清洗、规则过滤、字段标准化与异常记录。
- **身份认证：**适配 OAuth 2.0、CAS 等认证协议，完成身份映射、凭证校验与登录链路联调。
- **定制接口：**围绕各校的数据模型、接口协议和业务规则进行开发。
- **现场交付：**完成内网环境下的服务打包、环境配置、启动部署与问题排查。

## 设计与取舍 {#design}

### 01 / 为全量与增量数据建立明确链路

基于 Spring Boot、MyBatis 实现全量初始化与定时增量同步。面对不同业务系统的字段结构和数据口径，将清洗、过滤、标准化与异常记录组织到同步过程中，支持读者信息在多系统间稳定流转。

全量同步负责初始数据接入，增量任务按定时或实时方式更新。分别处理两类任务，有助于围绕不同的数据规模与更新节奏安排执行。

### 02 / 将身份认证适配到校内系统

通过 OAuth 2.0、CAS 等协议完成用户身份映射、凭证校验和登录链路联调，打通移动图书馆与校内多个业务系统的单点登录流程。

联调需要同时对齐接口协议、身份字段与实际登录流程，让认证结果能够正确对应到图书馆业务中的用户。

### 03 / 把院校差异收敛到映射与配置

在定制接口开发中复用通用数据处理流程，将各校的字段、协议与业务规则差异收敛到映射及配置层，减少重复开发，便于维护不同院校的接入逻辑。

### 04 / 把运行环境纳入交付过程

使用 Docker 与原生二进制包完成服务打包，根据不同院校的网络、数据库和运行环境完成部署配置与排查，覆盖接口开发、联调测试到现场交付的完整过程。

## 规模与验证 {#validation}

- **对接范围：**累计对接 16 个省份、上百所高校。
- **数据规模：**单次全量同步最高处理 6 万条读者数据。
- **更新方式：**增量任务定时或实时同步。
- **交付验证：**围绕读者数据同步、单点登录和定制接口开展联调，并完成高校内网环境部署与问题排查。

这段经历积累了异构系统接入与实际环境交付的经验，也让我在后续 Agent 开发中更关注状态管理、访问约束和运行过程的可追踪性。
